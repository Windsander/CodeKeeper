设计方案 3/4：数据流与构图算法

Daemon 如何把 EverOS 的扁平条目聚合成 Graph JSON

memory.graph handler 流程
  1. 调用 project.list 拿到所有项目。
  2. 对每个项目，调用 EverOS /api/v1/memory/get 4 次：
    memory_type=episode/profile/agent_case/agent_skill，枚举已知 user_id / agent_id
  3. 从返回条目中收集所有出现过的 user_id 和 agent_id，递归补拉遗漏 owner。
  4. 按规则生成 topicId、节点、边。
  5. 返回 { nodes: MemoryGraphNode[], edges: MemoryGraphEdge[], stats: MemoryGraphStats }。

topicId 推导规则

条目类型topicId 生成topic label
Reviewer agent_case / episodemr-<mrIid>（从 sessionId 正则提取）MR !42
Maintainer agent_case / episodemr-<mrIid> 或 discussion-<id>MR !42 / Discussion #7
Archiver agent_case / episodearchive-<date>-<slot>2026-06-30-0
Interaction episodediscussion-<id>Discussion #7
agent_skill无 topic，直接挂在 project 或 System 下—
profile无 topic，直接挂在 project 或 System 下—

跨项目/挂 System 的规则

  • agent_skill：若 source_case_ids 中 case 来自 ≥2 个项目，则 skill 节点挂到 CodeKeeper-System；否则挂到所属项目。
  • profile：同一 user_id 在多个项目有 profile 时，生成一个 System 级 profile 节点，原项目内不重复显示。
  • user/agent 节点：全局唯一，不重复按项目创建。

去重与截断策略

  • 节点按 type + id 去重。
  • 初始版本：返回全部节点，不做截断（假设项目/记忆量不大）。
  • 若未来性能问题：按时间倒序保留最近 N 个 topic，或按 score 截断叶子节点。
