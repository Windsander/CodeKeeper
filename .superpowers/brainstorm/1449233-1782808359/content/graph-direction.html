记忆可视化：三个设计方向

基于当前 MemoryBrowser 与 EverOS Graph Demo 的参考，下面是三种可落地的方案，点击选择倾向

A

纯前端关系图

Graph View（仅前端）
Episode —session→ Episode —source→ Skill —case→ Case

用现有 /search / /get 数据，按 session_id、source_case_ids、sender_id 生成节点与边。不新增后端接口。

  • 实现快，风险低
  • 无需改 EverOS
  • 边类型有限
  • 大数据量时前端重
B

后端聚合图接口 + 前端力导向图

Graph View（后端聚合）
你 —相关→ Project —包含→ Concept —实例化→ Fact

新增 IPC / EverOS 端点返回预计算图（节点+边）。可引入语义相似度边、实体节点（Person/Project/Concept/Fact/Organization）。

  • 边关系更丰富
  • 前端轻，支持大数据
  • 需要后端工作
  • 可能依赖 LLM 实体抽取
C

Graph View + Progress View 双页签

记忆浏览器新布局
Graph View | Progress View
过滤器
节点类型
时间范围
图/时间线画布

参考 EverOS Demo 的「Graph / Progress」切换。保留搜索能力，但用可视化图替代表格；Progress View 展示记忆增长曲线与每日时间线。

  • 与官方 demo 对齐
  • 兼顾宏观趋势与微观关系
  • UI 工作量较大
  • Progress 数据需统计接口

关键背景

  • EverOS 官方《Memory Graph Visualization》只有外部演示，仓库内无实现。
  • EverOS 后端目前只暴露 /search、/get 等条目接口，没有显式图/关系 API。
  • 项目当前无图可视化依赖（vis-network、D3、Cytoscape 等均未引入）。
