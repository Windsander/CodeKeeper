Graph View 交互

  • 类型过滤 chips：点击显示/隐藏某类节点，边跟随隐藏。
  • hover tooltip：显示节点类型、label、摘要、时间。
  • 点击节点：右侧滑出 detail panel，展示完整内容、关联节点列表、元数据。
  • 缩放/适配：右下角 +/- / fit 按钮。
  • 点击边：tooltip 显示边 label 与关联的原始记忆摘要。

Progress View 内容

  • 统计卡片：总记忆数、总关联数、活跃天数、项目数。
  • Memory Activity Heatmap：最近 N 天，按天着色（参考 GitHub contributions）。
  • Memory Growth（柱状图）：最近 14 天每日新增记忆数。
  • Daily Timeline：按天分组展示关键记忆卡片。

Progress View 的图表用纯 CSS/DOM 实现（不引入 chart.js/echarts），保持依赖最小。

新增横向边（A + C + D）

  • A. same_author：两个 topic 节点共享同一 user/agent 时连接。
  • C. related_skill：两个 agent_skill 有重叠 source_case_ids 时连接。
  • D. shares：两个 project 共享同一个 System 级 skill 或同一个 user 时连接。

测试计划

  • 单元测试：
    • graph-builder.test.ts：验证 topic 解析、节点/边生成、System 挂载逻辑。
    • memory-graph-handler.test.ts：验证 IPC handler 聚合流程与 owner 枚举。
    • 各 Runner 的 sessionId 生成测试。
  • 类型检查：npx tsc --noEmit、npx tsc -p tsconfig.electron.json --noEmit。
  • 手动验证：Electron 中打开记忆图，检查节点层级、过滤、detail panel、Progress View 数据。

风险与回退

  • owner 枚举不全：初次只能枚举已知 user/agent；新 owner 需通过递归发现补齐。
  • 性能：项目多/记忆多时 /get 调用次数多；可后续加缓存或截断。
  • vis-network 体积：需评估打包体积；如过大可换更轻量库。
